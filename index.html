CASE 01

一个按钮的音画练习

最开始的想法很简单：同一个按钮，点一下、按住和松开时，声音和画面应该有不同反应。

TAP短按，触发约 0.12 秒的声音和视觉事件。
PRESS按下以后先出现一小段 opening phrase。
HOLD超过 350ms，进入跟随 BPM 的持续状态。
RELEASE停止产生新事件，但保留 1–3 秒尾音和视觉残影。

右侧可以直接点击或长按；本页也支持按住 Space 演奏。

PROMPT 01

第一个可运行版本的提示词

做一个浏览器里的实验电子音画乐器。Visual 使用 WebGL 或 Canvas，声音使用 Web Audio API 或 Tone.js。整个系统只有一个主要按钮，并建立统一的 BPM / Transport。

短按 Tap：触发一个大约 0.12 秒的短促 transient，同时产生一个紧凑视觉事件。

按下 Press：启动一个大约 0.5–1 秒的 opening phrase，它和短按的声音不同。

长按 Hold：超过约 350ms 后进入持续状态，可以启动 drone、arpeggiator、短 loop 或 sequencer，并与 BPM 同步。音乐不能机械重复，每 1–2 小节从有限的 pattern variant 中发生小变化。

松开 Release：停止产生新的主事件，但进入一段独立的 release phrase，并保留 delay、reverb 和视觉 residue，在 1–3 秒内衰减。

Idle：没有输入以后不要立刻归零，保留轻微 ambience / memory，再慢慢回到安静状态。

声音偏实验电子、ambient electronic、organic、略带颗粒感。随机只能发生在限定范围内。Audio 与 Visual 读取同一个 clock 和 state。

使用时可以替换的部分

  1. 声音风格与速度
  2. Tap / Hold / Release 的时长
  3. 持续状态里的音乐模块
  4. 视觉对象：粒子、拓扑、波纹或几何
  5. 随机变化的范围

TECH NOTES

声音与视觉分别怎样实现

Tone.js适合需要 BPM、Transport、音序器、Loop 和效果器的版本。做节拍同步和长按持续演奏会比较省事。
Web Audio API浏览器原生音频接口。可以做振荡器、滤波、混响、频谱分析，也可以把麦克风或音频文件的数据交给视觉。
Canvas 2D适合先验证波纹、轨迹、形状变化和简单粒子。代码少，修改反馈快。
Three.js / WebGL适合大量粒子、三维空间、相机运动、着色器和更复杂的现场视觉。
我常用的一组共享参数： BPM、beat、bar、energy、state、holdDuration、releaseAmount、patternVariant。声音和视觉都读取这组数据，而不是声音做好以后再额外加一个频谱动画。

REVISION LOG

试玩以后，我继续修改了什么

问题：长按太机械

声音和画面一直重复同一个循环，十几秒以后就没有变化了。

Hold 期间不要完全随机。保持同一个 BPM 和主节奏，每 2 小节只在 density、filter cutoff 或 octave 中选择一项做小幅变化，并限制为 3–4 个固定 variant。
问题：声音越叠越乱

每次触发都增加新声音，调性、并发数量和总音量没有边界。

限定同一套音阶；同时发声不超过 4 个 voice；增加 master limiter。新的音符只能从当前 pattern 和 chord tones 中选择。
问题：视觉只会闪

视觉只是读取音量大小，没有表现 Tap、Hold 和 Release 的差别。

不要只做频谱动画。Tap 生成一个节点；Hold 让节点连接、分裂和扩散；Release 停止生成，已有连接继续衰减 2–3 秒。三种状态读取同一个 state。

保存方式：做出一个能运行的版本 → Git Commit → 只改一个问题 → 测试 → 看 Diff → 保留或回退。

CASE 02

Stellar Synth｜星宿合成器

项目里的三个部分

最早只是验证“一颗星能不能同时触发一个声音和一个视觉事件”。后来加入不同文明的星图、星座演奏和自动演奏模式。

星图数据恒星位置、星等、连线与星座结构，决定音符顺序、密度、力度和声像。
不同文明的音乐设置继续整理各自的音阶、节奏、乐器音色和演奏装饰，避免只贴“民族风格”标签。
统一的编曲框架准备放进 Melodic Techno 的 BPM、Kick / Bass、8 或 16 小节乐句与能量推进中。

目前：星图、交互与视觉已经可以体验；文明音乐语汇和完整编曲仍在继续制作。
